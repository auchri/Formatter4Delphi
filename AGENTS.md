# Codex working instructions

1. Start with [design/README.md](design/README.md). The target architecture is governed by [requirements](design/docs/spec/01_PRODUCT_REQUIREMENTS.md), then the [canonical API/data contracts](design/docs/spec/14_CONTRACTS.md); other design/spec documents and ADRs elaborate these contracts. Follow [implementation contribution rules](design/CONTRIBUTING_IMPLEMENTATION.md) for scoped work and evidence.
2. Documents under docs/ describe implemented APIs, tests, historical milestones and decisions. Consult [CST_SPEC](docs/CST_SPEC.md), [LEXER_SPEC](docs/LEXER_SPEC.md), [M2_STATUS](docs/M2_STATUS.md) and related evidence for the actual baseline; they are not competing normative target specifications. Target APIs in design/ are not automatically implemented.
3. The specification authorizes no implementation. Implement only an explicitly commissioned milestone with named scope, requirements and acceptance criteria from the [target implementation plan](design/docs/spec/09_IMPLEMENTATION_PLAN.md). No implementation milestone is currently active. Stop at the commissioned boundary.
4. Baseline is implemented M2.7 analysis tooling over M2.6 parser grammar. PR #10 is a separate M2.8 pilot; do not merge, copy, reject or assume its integration as part of A0. Follow the [baseline strategy](design/docs/spec/12_CURRENT_CODE_AUDIT.md) and verify current SHAs/PR status before new implementation work.
5. Use Delphi 12.3-compatible Object Pascal and RTL, no VCL/FMX in core. DUnitX is the only test dependency. Prefer Win64/Debug and keep core platform-neutral.
6. Preserve existing public APIs, token kinds and enum ordinals unless an explicitly justified migration is in scope. No unnecessary lexer, token-model or arena rewrite. Follow the canonical owner/dependency contracts.
7. Preserve every UTF-16 code unit, including malformed ones. Every original token including EOF occurs exactly once in CST leaf order. Serialization traverses leaves, never returns the stored source wholesale. Spans are half-open, zero-based UTF-16; Delphi string indexing is one-based. Byte offsets are separate. Missing tokens are zero-width with no original index/text.
8. Every scanner/parser loop consumes a token, exits or returns. Ordinary syntax errors produce diagnostics and lossless recovery. API misuse is distinct. Unsupported, incomplete and context-unknown syntax remains protected; structure alone grants no formatting permission. No preprocessor or include resolver.
9. Use generic immutable syntax nodes and explicit trivia leaves. The tree owns the element arena; roots/children are borrowed. No parent pointers, class per production, green/red trees or speculative concurrency.
10. Roundtrip alone is insufficient: assert hierarchy/roles, spans, operator grouping, diagnostics and exact token order. Keep tests deterministic, add bug regressions, verify lifetime after lexer disposal and repeated allocation/freeing. Never format parser input files. Preserve the pinned M2.7 corpus, hashes and decoding policy.
11. Run scope-appropriate checks and, for code changes, real compilation/tests when the toolchain is available. Verify fresh EXE/DCU artifacts and exact toolchain; CE 12 Update 1 is not Delphi 12.3. Never claim unexecuted results or trust exit code alone. Documentation-only work uses the [document validator](scripts/ValidateDesignDocs.ps1); no unnecessary runtime rebuild.
12. Protect independent uncommitted work; inspect status and secure changes before switching branches or staging. No AST, compiler, preprocessor, LSP or IDE-plugin implementation. No new parser/formatter/config features without a separate explicit commission. Create/update a PR only when requested and never automatically merge.
13. Finish with changed files/classes, actual supported versus planned behavior, checks performed, limitations and the next bounded task. Record newly proven language/API deviations in the affected design ADR and implementation evidence; do not silently reinterpret old milestones as current instructions.
